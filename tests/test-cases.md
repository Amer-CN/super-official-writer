## 一、单元测试（规则合规性）

### UT-01: V+N/N+V 分布检测

**输入**：生成一篇工作总结（约800字）
**预期**：
- [ ] 全文 V+N 占比 ≥ 50%
- [ ] 文章后半部分（50%以后）N+V 出现次数 = 0 或接近0
- [ ] 不以"我们""本单位"开头

### UT-02: 首段「按·拿·推」结构

**输入**：生成一份工作汇报的首段（约150字）
**预期**：
- [ ] 包含"按"元素（政策依据/上级要求）
- [ ] 包含"拿"元素（具体做法/措施组合）
- [ ] 包含"推"元素（成效/目标/方向）
- [ ] 三者顺序正确：按→拿→推

### UT-03: 3V+N 句式

**输入**：生成一个描述工作措施的段落
**预期**：
- [ ] 至少出现一个包含3个递进动词的句子
- [ ] 动词遵循递进逻辑（从虚到实/从准备到落实/从上到下）

### UT-04: Protected Spans 保护

**输入**：
> 请写周报。本周完成 [[3]] 个重点项目，投入资金 [[128.5万元]]，参与人员共 [[47]] 人。

**预期**：
- [ ] 输出中保留数字 "3"、"128.5万元"、"47"
- [ ] 数字未被修改或模糊化

### UT-05: 四大金刚完整性

**输入**：随机抽取5个句子
**预期**：
- [ ] 每个句子可识别出 目标/过程/措施/结果 四要素
- [ ] 缺失要素 ≤ 1个/句

### UT-06: 风格引擎切换

**输入**：同一份周报数据，分别用 S1/S2/S3/S4/S5/S6 六种风格生成
**预期**：
- [ ] 6种输出有明显风格差异
- [ ] 核心事实数据在6种输出中一致

## 二、对抗性测试（边界情况）

### AT-01: 素材极度匮乏

**输入**："帮我写一份年度工作总结"
**预期行为**：
- [ ] 不凭空编造数据和事迹
- [ ] 输出框架模板 + 提示用户补充关键信息
- [ ] 不触发幻觉生成虚假成就

### AT-02: 矛盾的风格参数

**输入**：写周报，S6（精要速报）+ 详略度5（最详实）
**预期行为**：
- [ ] 检测到参数矛盾并给出警告
- [ ] 选择一种合理折中方案或询问用户

### AT-03: Protected Spans 与风格引擎冲突

**输入**：写周报，S6（极限压缩），但用户提供了大量详细数据作为 Protected Spans
**预期行为**：
- [ ] Protected Spans 数据完整保留
- [ ] 风格压缩作用于非 Protected 部分
- [ ] 不为了压缩而删除用户数据

### AT-04: 敏感政治表述

**输入**：写一份涉及敏感话题的材料
**预期行为**：
- [ ] 不自行编造政治表态
- [ ] 引用上级精神时标注需用户确认
- [ ] 触发诚实边界第5条（政治敏感性判断）

### AT-05: 超长材料请求

**输入**：写一份5000字的政府工作报告
**预期行为**：
- [ ] 结构完整（符合T4框架）
- [ ] 各部分比例合理
- [ ] 不在前半部分就耗尽"干货"

### AT-06: 跨文体混淆

**输入**：写一份"既是周报又是讲话稿"的东西
**预期行为**：
- [ ] 识别文体冲突
- [ ] 要求用户明确选择一种文体
- [ ] 或分别生成两个版本

## 三、端到端测试（完整流程）

### E2E-01: 完整周报生成

**步骤**：
1. 输入周报需求 + 本周工作数据
2. 执行 Step 1→5 完整流程
3. 通过8项算法校验

**通过标准**：
- [ ] 五步法每步都有产出
- [ ] 8项校验全部通过
- [ ] 用户可读、可直接提交

### E2E-02: 从素材到讲话稿

**步骤**：
1. 提供500字原始素材（会议记录/工作笔记）
2. 要求生成事前类领导讲话稿
3. 对比原始素材与最终输出的信息保真度

**通过标准**：
- [ ] 原始素材的关键信息无丢失
- [ ] 输出符合事前类讲话稿框架（T6-A）
- [ ] 地空对接到位

### E2E-03: 多轮迭代修改

**步骤**：
1. 生成初稿
2. 用户反馈："第二部分太虚了，要多加数据"
3. 修改后重新输出
4. 用户反馈："结尾太套路，换个方式"
5. 再次修改

**通过标准**：
- [ ] 每次修改精准定位问题
- [ ] 不破坏已确认的部分
- [ ] 修改次数 ≤ 3次达到满意
