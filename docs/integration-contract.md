# 集成契约（Integration Contract）

> 本文件面向**下游集成者**：把本 skill 作为外部依赖接入自己产品的开发者（包括作者自己的"工程管家·文秘助手"模块）。
> 普通用户（把 skill 装进 Agent 直接对话使用）**无需读本文件**——契约不改变任何使用方式。
> 契约随仓库同版本演进：你在 SKILL.md 第 3 行看到的版本锚点是 v几，本文件就是那个版本的承诺；契约本身的修订也会记录在 CHANGELOG.md。

## 一、稳定面（Stable Surface）

以下结构被下游按**编号/格式**程序化解析。改动它们属于 **breaking change**：

### 1. SKILL.md 章节编号

- H2 章节标题 `## 一、` 至 `## 十、`——下游按章节前缀抽取对应章节全文，注入自己产品的 prompt
- 第七节内的小节标题 `### 7.1` / `### 7.2`——下游按小节号定位

### 2. templates.md 模板编号

- 模板标题 `## T1.` 至 `## T21.`——下游按编号解析文体框架
- 各模板内的子形态标题 `### A.` / `### B.` / `### C.` / `### D.`

### 3. 版本锚点（热更比对依据）

- 位置与格式固定：SKILL.md **第 3 行** `<!-- skill-version: vX.Y -->`
- **格式不可变；版本只能递增**——下游（及 scripts/version_check.py）以此做热更版本比对

## 二、变更规则

- ✅ **允许（非 breaking）**：
  - 追加新章节（如 `## 十一、`）、新 T 编号（如 `## T22.`）、新小节
  - 各稳定面**内部的正文文字**修订（这正是 skill 迭代的知识增量）
  - 新增其他文件
- ❌ **禁止（breaking）**：
  - 删除、改名、重排已有编号（章节号/小节号/T 编号/子形态字母）
  - 变更版本锚点的格式或位置
  - 移动上述文件

## 三、breaking change 的标记义务

发生 breaking change 时，维护者**必须**：
1. 递增 SKILL.md 第 3 行版本锚点；
2. 在 CHANGELOG.md 对应版本条目中以 `**breaking**` 字样标注，并写明受影响的稳定面与迁移方式。

## 四、非稳定面（下游不得依赖）

- `references/corpus/INDEX.md`：脚本自动生成，条目与计数随时变化——需要知识请按章节抽 SKILL/层文件，勿解析 INDEX
- 各章节/模板**内部的正文措辞**：随时在修订（按编号抽取全文是稳定用法，按行号或固定措辞匹配不是）
- `check_params.py` 的 stdout 排版：仅供人读；其 **exit code（--final 0=合规/1=不合规）** 属稳定接口
